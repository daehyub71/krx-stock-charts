# SPEC — krx-stock-charts (v1.0)

> 상태: **확정** (2026-08-15 사용자 확정 — §8 D1~D6 결정 완료)
> 변경 시 이 문서를 먼저 고치고 PLAN → DESIGN → TASKS 순으로 역추적한다.

## 1. 개요·목표

한국 주식시장(KOSPI200 중심 주요 종목)의 **3년치 일봉 데이터**를 수집하고,
**일봉·주봉·월봉을 파이프라인에서 사전 계산**해 저장한 뒤,
웹 대시보드에서 종목을 검색해 캔들 차트를 볼 수 있는 서비스.

- 데이터 소스: **pykrx** (KRX 공식 데이터, API 키 불필요)
- 수정주가 적용 — 액면분할·증자로 인한 3년 차트 왜곡 방지

## 2. 기능 요구사항

| ID | 요구사항 | 상세 |

| F2 | 3년치 일봉 백필 | 전 대상 종목의 OHLCV(시가·고가·저가·종가·거래량·거래대금) 3년치 1회 수집 |

| F5 | 종목 검색·선택 | 대시보드에서 종목명/티커로 검색, 종목 선택 |

## 5. 데이터 모델

Supabase(PostgreSQL)에 저장한다. 같은 프로젝트에 다른 서비스의 테이블이 있으므로
**모든 테이블에 `ksc_` 접두어**를 붙인다. 스키마 원본은 `supabase/schema.sql`.

### `ksc_tickers` — 종목 메타 (F1)

| 컬럼 | 타입 | 비고 |
|------|------|------|
| `ticker` | text PK | 6자리 영숫자. `^[0-9A-Z]{6}$` 제약 — 숫자만 아니다 (예: `0126Z0`) |
| `name` | text | 종목명 |
| `market` | text | KOSPI / KOSDAQ |
| `sector` | text | 업종명 |
| `updated_at` | timestamptz | |

### `ksc_bars` — 봉 데이터 (F2·F4)

일·주·월봉을 한 테이블에 `timeframe`으로 구분해 담는다.

| 컬럼 | 타입 | 비고 |
|------|------|------|
| `ticker` | text | → `ksc_tickers` FK |
| `timeframe` | text | `daily` / `weekly` / `monthly` |
| `d` | date | 주봉·월봉은 **구간 마지막 거래일** |
| `o` `h` `l` `c` | integer | 시·고·저·종가 (원) |
| `v` `a` | bigint | 거래량(주) · 거래대금(원) |

- **PK `(ticker, timeframe, d)`** — 같은 봉을 다시 쓰면 덮어써진다. 이것이 멱등성(N1)의 근거다.
- 인덱스 `(ticker, timeframe, d desc)` — 차트 조회 패턴에 맞춘다.
- **DB 제약이 검증을 강제한다**: 가격 > 0, `h >= max(o,c)`, `l <= min(o,c)`, `h >= l`.
  `validate.py`가 놓쳐도 오염된 행은 저장 자체가 거부된다.
- 리샘플 규칙: 시가=구간 첫 봉 시가, 종가=구간 마지막 봉 종가, 고가·저가=구간 최고·최저, 거래량·거래대금=합계
- 주 경계는 **월요일 시작**(ISO 주), 월 경계는 역월 기준

### `ksc_meta` — 실행 메타

`key`(text PK) / `value`(jsonb) / `updated_at`. 데이터 기준일·행 수·마지막 갱신 결과를 담는다.

### 접근 권한 (RLS)

- 세 테이블 모두 RLS 활성화. `anon`·`authenticated`에 **SELECT만** 허용.
- 파이프라인은 `service_role` 키로 쓴다 (RLS 우회). **이 키는 웹 번들에 절대 넣지 않는다.**
- 웹은 `anon` 키로 읽기만 한다 — anon 키는 공개되어도 RLS가 쓰기를 막는다.

## 6. 제약 조건·리스크

- pykrx는 KRX 웹 스크래핑 기반 — KRX 사이트 개편 시 파손 가능. 갱신 실패 시 기존 데이터 유지(F7)
- 수정주가(D5 적용)는 액면분할·증자 시 **과거 값이 소급 변경**된다. 갱신 시 최근 20거래일 종가를 저장분과 대조해 불일치 시 해당 종목 전체 재백필
- 주봉/월봉을 사전 계산하므로, 일봉이 갱신되면 **해당 종목의 마지막 주봉·월봉도 함께 갱신**해야 한다 (진행 중인 주/월의 봉은 매일 변한다)
- KOSPI200 구성 종목은 정기 변경됨 — 편입 종목은 자동으로 3년 백필 대상에 포함
- 개인 학습·분석용 — 투자 자문 아님, 실시간 시세 아님(전일까지)
- **pykrx 1.2.8+는 종목목록·지수구성종목 조회에 KRX 계정을 요구**한다 (OHLCV는 불필요).
  `KRX_ID`/`KRX_PW`를 `.env`(로컬)·Secrets(CI)로 주입한다

### D4 변경에 따른 영향 (2026-08-15)

**사유**: 사용자 확정. 파생 로직이 Python 한 곳에만 존재하게 되어 언어 간 구현 불일치 위험이 사라진다.

| 영향 | 내용 |
|------|------|
| 데이터 모델 (§5) | `data/daily/`만 있던 구조 → `daily/` `weekly/` `monthly/` 3개 디렉토리 |
| 저장량 (N3) | 약 +26% (주봉 ~157행, 월봉 ~37행이 종목당 추가) |
| 파이프라인 | `resample.py` 모듈 추가, 갱신 시 마지막 주/월 봉 재계산 필요 |
| 프론트 | `resample.ts` 불필요 — 파일을 그대로 읽어 lightweight-charts에 전달 |
| 테스트 | Python↔TypeScript 리샘플 대조 테스트 불필요 (구현이 하나뿐) |

### D2 변경에 따른 영향 (2026-08-15, 재확정)

**사유**: 사용자 확정. 정적 JSON을 매일 GitHub에 커밋하면 파일이 통째로 새 blob이 되어
히스토리가 연 약 900MB씩 누적된다(리포 권장 한도 1GB). Supabase는 이 문제가 없다.

| 영향 | 내용 |
|------|------|
| 저장 (§5) | `data/*.json` → `ksc_tickers` / `ksc_bars` / `ksc_meta` 테이블 |
| 파이프라인 | `store.py`가 파일 쓰기 → Supabase upsert. `supabase>=2.7` 의존성 추가 |
| 검증 | DB 제약(CHECK)이 OHLC 정합성을 강제 — `validate.py`의 2차 방어선 |
| 웹 | 빌드 시 정적 파일 로드 → anon 키로 Supabase 조회. 매일 재배포 불필요(데이터가 항상 최신) |
| 자격증명 | `SUPABASE_URL`·`SUPABASE_SERVICE_KEY`(파이프라인)·`SUPABASE_ANON_KEY`(웹) 추가 |
